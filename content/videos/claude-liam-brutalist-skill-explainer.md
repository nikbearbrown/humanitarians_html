Every other explainer skill in this video toolkit inherits from one parent, simply called explainer, not the AI-branded cut, not the CLI cut, not the deep cut. Reading its SKILL.md directly answers what it actually is and how it decides what ends up on screen.

## The easy mistake

The first assumption most people make is that this skill defines a look: cream paper, editorial serif type, hand-drawn rings. It doesn't. It's a pipeline. It launders any source thrown at it, an archive photo, a Manim fragment, a public domain reel, through one consistent treatment. The sources never match each other. The treatment does. That's why a film built from wildly different source material still reads as one coherent film.

## The anatomy

A skill in this toolkit is a folder Claude reads before working, and the explainer folder is larger than most because it governs everything downstream. SKILL.md is the core doctrine. A motion reference file holds a pantry of seven motion languages. A Remotion reference file specifies the annotation plane. An equations reference file provides the equation-tangent template. A scripts folder holds the runtime: the audio maker, the pantry cropper, the compiler, the outro machine. Every other explainer skill in the toolkit extends this one.

## The pipeline

The flow runs: script becomes beats, beats become a Kokoro voiceover, free and local, which serves as the master clock. Media flows in per beat from four sources: Manim fragments, treated stills over a Ken Burns pan, public domain footage, and motion annotations. A compile step conforms every slot to the audio window and produces one watchable master. That's the entire loop; everything else is a modifier layered on top of it.

## The laundering thesis

The skill file states its own thesis directly: it is not a style, it is a laundering function. Any source fed into it, an archival photo, a generated still, a public-domain reel, a Manim fragment, a motion card, passes through the same treatment: desaturated by roughly 80 percent, contrast raised to about 1.15, seated on a scanned newsprint texture. That single shared treatment is why mixed media reads as one film rather than a patchwork of different visual sources.

## Two independent tags per beat

Every beat carries two separate tags. Shot type is the presentation form, still, footage, document, graphic, composite, or title card, and it gets locked at the planning stage and never changes afterward. Shot source is the provenance, whether it came from an archive, an AI generator, or a user's own file, and it's late-bound and swappable. Keeping these two tags separate is deliberate: collapse them into one, and every media swap becomes a full re-edit. Keep them separate, and swaps are free, drop a new file into the media slot and only that one slot recompiles.

## The slot contract

Every beat on the timeline resolves to one conformed MP4 per beat, and the precedence at compile time runs: a hand-added MP4 in the media folder beats a Manim-rendered beat, which beats a still image with Ken Burns motion, which beats a placeholder slate. That ordering means the very first compile pass is always a watchable film, with slates standing in for anything not yet supplied. A slate is a normal production stand-in, not a defect; it marks a slot to be filled later. Changing a slot's input recompiles only that one clip, leaving the rest of the reel identical.

## When a still earns its place

The skill's sharpest rule concerns when a still image belongs in the film at all: a still exists for exactly one reason, because it is the evidence, the actual document or record the argument turns on, not because it looks appropriate. The test is a single question: could this still be swapped for any other still of the same general subject without changing what the beat proves? If yes, it's decoration and should be cut, letting a Manim or Remotion beat carry the idea instead. A pantry still is the most expensive kind of beat in the system, worth paying for when it's genuine evidence, never worth it as atmosphere.
