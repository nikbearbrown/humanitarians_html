Two people can use the exact same Claude model for a week and get completely different results. One person's answers stay generic no matter how they phrase the question. The other person's answers get sharper by day three. The difference isn't skill at prompting and it isn't a smarter model, it's what each person gave Claude to work with.

## Why a blank chat behaves like an empty project

Every new Claude chat starts with nothing: no files, no history, no memory of last week's conversation. That's obvious for a fresh chat. What's less obvious is that a Claude project behaves exactly the same way if it's created but never loaded with real material. The label changes, it says "project" instead of "chat", but the context Claude actually sees hasn't changed. Files sitting in a project that nobody ever opens or references don't help either. A project only works differently from a blank chat once it's actually stocked with the documents someone would otherwise keep explaining over and over.

## The one move that changes the output

The fix isn't more clever prompting. It's loading the three documents you find yourself re-explaining most at work into one project. Once a project is genuinely loaded, real documents, a real ongoing thread, Claude stops defaulting to generic responses and starts answering as if it already knows the context of your work. That's the entire mechanism: feed it what it needs, and the output stops being generic.

## What to actually do tonight

Pick the documents you re-explain most: the policy nobody remembers, the background a new hire always needs, the reference sheet you paste into every third conversation. Put them in one project. That's the whole move, no special formatting, no elaborate setup, just the real files a new teammate would need to understand your work.

## The prompt to try

The video's suggested move is to paste your documents into a Claude project along with this request: "Here are the documents I keep re-explaining at work. Read them, then tell me what a new teammate still wouldn't understand, and what I should add to this project so I never have to explain it again." That prompt does two things at once: it tests whether the documents actually cover what people need to know, and it surfaces the gaps before they cost you another re-explanation.

## Key takeaways

- A blank chat and an empty (or unloaded) project produce the same generic results, creating a project isn't enough on its own.
- Claude can't know what it was never told; the model isn't under-powered, it's under-fed.
- The fix is concrete: load the three documents you re-explain most often into a single project.
- Files added to a project but never referenced don't change anything, loading has to mean the documents are actually part of what Claude reads.
- A short audit prompt ("what would a new teammate still not understand?") is a fast way to check whether a project is genuinely stocked or just labeled.

## Who this is for

Anyone who has used Claude for basic tasks but feels like the answers stay surface-level no matter how the question is phrased, especially people who haven't yet tried Claude Projects as a way to carry real, recurring context between conversations.
