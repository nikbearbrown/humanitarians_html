Liam, in for Bear, takes on a natural but wrong assumption: that Claude "learned" how to write client letters from a skill called client-letter. It did not. It was handed a file of instructions, and client-letter is just the name of that one file.

## Why this sounds like a capability upgrade

When Claude has a client-letter skill available, it sounds like a writing upgrade, as if it studied real client letters and came back knowing how to counsel someone in its own words. But nothing about the model itself changes when a skill is added. Delete the skills folder and Claude does not forget how to write client letters, because there was nothing to learn in the first place. It just stops following that one routine.

## What a skill actually is

A skill is one file. The client-letter skill is a folder holding a single SKILL.md file, containing instructions for turning a case update into a clear client letter, written in plain language that Claude reads before it starts. Claude reads that file top to bottom and works through it step by step, in the order it is written, with no branching unless the file itself says to branch.

## Specification, not power

This makes a skill a specification, not a new capability. The payoff is a consistent structure applied to every letter: what happened, what it means, what happens next. The limit is that anything outside those written steps is genuinely off the map for that routine. The client-letter skill never taught Claude how to counsel a client. It guarantees only that every time it runs, Claude reads the same file and produces the same letter structure.

## Neither a good letter nor a bad one proves much

The video makes a point of running this in both directions. Watching Claude produce a clear client letter does not prove it understood the underlying matter, a file can be followed precisely on a case Claude never really grasped. Equally, watching it produce a clumsy letter does not prove the skill itself is broken, it may simply be a case the file's structure does not fit well. Neither outcome is proof of understanding or its absence.

## Try it yourself

The video closes with a direct prompt: pick one document you produce the same way every time, ask Claude to write a SKILL.md for it in plain language with ordered steps, then have it read that file back to you and walk through exactly what it will do before doing it. Running this against a document you actually produce repeatedly shows the mechanism directly, rather than taking the claim on faith.

## Key takeaways

- A Claude skill is a specification the model follows, not a capability it learns or internalizes.
- Deleting a skill's folder does not erase any ability, because nothing was actually learned, Claude just stops following that one routine.
- The client-letter skill's payoff is a consistent letter structure, what happened, what it means, what happens next, every time it runs.
- The limit of a skill is anything its written steps never cover; Claude does not improvise beyond the file.
- A well-written or poorly-written output is not evidence, on its own, of whether Claude understood the underlying matter.
